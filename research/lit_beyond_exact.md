# Literature: variants beyond exact token-ID n-gram lookup (ICE), 26 Oct 2026

Verification: every id below was returned by a web search as an arXiv URL whose title matched. The four 2026 papers (2607.02303, 2609.35578, 2606.08347, 2601.07372) were opened directly. Nothing was invented. Summaries of older papers are from search snippets, not full-text reads.

## A. Closest to ICE / novelty risk

1. **A Hippocampus for Linear Attention (HOLA)**, W. Cui, 2026, arXiv 2607.02303 (opened). GDN-style delta-rule state plus a bounded exact KV cache. It keeps only tokens with high write residual (beta*||e||) and uses a sharpened read. 340M, 15B tokens: Wikitext ppl 27.32 to 22.92, and RULER recall to 32k beats GDN. Memory is a KV subset, so it costs far more bytes/token than ICE. Risk: it is the same story (a hybrid recurrent model loses exact recall, fixed by an exact side memory). It is the strongest competitor for the "fix GDN recall cheaply" claim. Extension: frame ICE as the much cheaper (~41 B vs KV) alternative and run a bytes-per-token vs recall Pareto against it.
2. **In-Context Language Learning: Architectures and Algorithms** (n-gram heads), Akyurek, Wang, Kim, Andreas, ICML 2024, arXiv 2401.12973. Transformers win at in-context language learning through n-gram heads, which are higher-order induction heads. Hard-wiring these heads into 340M models gives -1.14 ppl on SlimPajama. Risk: conceptual precedent for "inject an n-gram successor distribution". But it is an attention-based head with a KV cost, not a CPU table. Extension: use it as the "learned soft version" baseline; its distribution over successors motivates ICE returning a distribution, not one token.
3. **Birth of a Transformer: A Memory Viewpoint**, Bietti, Cabannes et al., NeurIPS 2023, arXiv 2306.00802. Induction heads viewed as associative memory for in-context bigrams. Theory backing for why a lookup table of "what followed last time" is a natural primitive. Extension: cite for motivation. The n-gram-order gating can be justified by it.
4. **Pointer Sentinel Mixture Models**, Merity et al., 2016, arXiv 1609.07843, and **Improving Neural LMs with a Continuous Cache**, Grave et al., 2016, arXiv 1612.04426. A pointer or cache over recent context is mixed with the vocabulary softmax. The cache uses hidden-state similarity as the key. Risk: ICE's output-side bonus is a hard-key cousin of the neural cache, so cite and differentiate. Extension: add a cache-style distribution over ALL matched successors (counts), not just s*.
5. **Infini-gram**, Liu, Min, Zettlemoyer, Choi, Hajishirzi, COLM 2024, arXiv 2401.17377. Suffix-array longest-match infinity-gram with backoff. 47% next-token accuracy, which is very close to ICE's 46.7% day-0 figure. It complements neural LMs at inference only. 7 B/token on disk. Extension: ICE is an in-context, causal, training-integrated infini-gram. Also **Infini-gram mini**, arXiv 2506.12229 (FM-index, snippet only).

## B. Candidate sets and span retrieval (multiple successors, spans)

6. **SuffixDecoding**, Oliaro, Jia, Campos, Qiao, NeurIPS 2025, arXiv 2411.04975. Suffix trees over prompts and prior outputs. Drafts adaptively, using longer drafts when acceptance is likely. Up to 5.3x on SWE-Bench. Extension: swap ICE's single successor for the top-k branches with counts, and use the branch-probability mass as the trust feature. This is cheap on CPU.
7. **SAM-Decoding**, Hu et al., ACL 2025, arXiv 2411.10666. Static plus dynamic suffix automaton. Exact longest match in amortized O(1) per step. Extension: replace the ICE hash tables for orders {1,2,3,4,6,8} with one automaton. This gives the true longest match and the full successor set, with no fixed orders.
8. **REST**, He et al., NAACL 2024, arXiv 2311.08252. Retrieves continuations from a datastore for drafting. A precedent for retrieved candidates as a draft tree. Extension: ICE-style multi-candidate drafts from in-context history.
9. **Token Recycling**, Luo et al., ACL 2025, arXiv 2408.08696. An adjacency matrix of top-k successor tokens per token, under 2 MB. Extension: ICE variant "top-k successors of the last n-gram with counts" as a compact per-document successor table. Bytes/token stay tiny.
10. **NEST (Nearest Neighbor Speculative Decoding)**, Li et al., NeurIPS 2024, arXiv 2405.19325. Mixes a token-level kNN distribution with the LM. Extends the retrieved token to a span when confidence passes a threshold. Extension: the same confidence-triggered span extension on ICE: if the n=8 match is confident, also feed the next 2-4 successor tokens.
11. **Copy Is All You Need (COG)**, Lan et al., ICLR 2023, arXiv 2307.06962. Generation as copying phrases from a corpus using indexed contextual phrase vectors. Extension: feed span features (the next k tokens) in place of one successor. Precedent for span-level copy.

## C. Matching on learned / hidden-state keys (fuzzy, semantic)

12. **kNN-LM**, Khandelwal et al., ICLR 2020, arXiv 1911.00172. Hidden-state keys with next-token values, interpolated with the LM. Gives fuzzy and paraphrase matching, but needs a dense datastore (d floats per token). Extension: quantize the keys (see 13, 15).
13. **Efficient kNN-LM**, He, Neubig, Berg-Kirkpatrick, EMNLP 2021, arXiv 2109.04212. Adaptive retrieval, datastore pruning, PCA. Up to 6x speedup. Trains a small adaptor for the interpolation weight from neural and count features. Extension: copy the adaptor idea: a learned gate on ICE using match-length and agree features. This is basically ICE trust, which barely helped.
14. **You can't pick your neighbors, or can you?**, Drozdov et al., Findings EMNLP 2022, arXiv 2210.15859. Interpolation weight set by retrieval quality (similarity buckets). About 4% ppl gain. Also **KNN-LM Does Not Improve Open-ended Text Generation**, arXiv 2305.14625 (snippet), which finds retrieval is less reliable on model-generated queries. Direct precedent for ICE's trust buckets and its over-reliance finding. Extension: calibrate the logit bonus post hoc per bucket (temperature and bias) rather than training it jointly.
15. **Reformer (LSH attention)**, Kitaev et al., ICLR 2020, arXiv 2001.04451. Random-projection hashing groups similar vectors into buckets. Extension: SimHash of a mid-layer hidden state (e.g. 16-32 bits, 2-4 B/token) as a second key type. Look up the most recent position with the same code and return its successor. This is fuzzy ICE, costing about 4 B/token more. Risk: collisions and training needs a hash that stays stable, so use a frozen random projection of a frozen early-layer state.
16. **Memorizing Transformers**, Wu, Rabe, Hutchins, Szegedy, ICLR 2022, arXiv 2203.08913. kNN attention into a (K,V) memory. Up to 262K tokens. Full KV cost. This is the upper-bound baseline on bytes/token. **Landmark Attention**, Mohtashami and Jaggi, NeurIPS 2023, arXiv 2305.16300: block-level retrieval through landmark tokens, extends to 32k. Extension: block-level (chunk) retrieval stores one vector per 64 tokens, about 32x cheaper than KV. A middle point between ICE and KV.
17. **RETRO**, Borgeaud et al., 2021, arXiv 2112.04426. Chunk-level retrieval with chunked cross-attention. Extension: in-context RETRO over earlier chunks of the same document, with frozen chunk embeddings.

## D. Static n-gram and lookup memories inside LMs

18. **Engram (Conditional Memory via Scalable Lookup)**, DeepSeek/PKU, Jan 2026, arXiv 2601.07372. Hashed 2- and 3-gram embedding tables injected into layers, with context-aware gating. O(1) lookup, prefetchable, CPU-offloadable. It is static (learned over the corpus), not in-context. Extension: ICE is its in-context dual. Combine the two ("static Engram plus in-context ICE") for a clean 2x2 story. Reuse its gate design.
19. **FactorEngram**, Yang et al., Sept 2026, arXiv 2609.35578 (opened). Factorized n-gram memory with basis-level gating. Extension: basis-level gating of ICE's successor embedding, so the model uses parts of the retrieved embedding. This may help the over-reliance problem. **Tensorizing Engram (TN-gram)**, Zhou et al., June 2026, arXiv 2606.08347 (opened): shared CP factors across n-gram orders. Extension: share factors across ICE orders.
20. **Over-Tokenized Transformer (Over-Encoding)**, Huang et al., 2025, arXiv 2501.16975. Hashed n-gram input embeddings. A 128x larger input vocab lets a 400M model match a 1B baseline. Extension: static n-gram input vocab as a control arm. It shows gains are not just copying.
21. **N-Grammer**, Roy, Anil et al., 2022, arXiv 2207.06366. Discrete latent (VQ-style) bigram IDs added to a Transformer. The nearest precedent for quantized semantic n-grams. Extension: cluster the layer-2 hidden state into codes (k-means, 256-4096 codes), then build n-grams over codes. This gives "semantic n-grams" with paraphrase tolerance at 1-2 B/token.
22. **Large Memory Layers with Product Keys**, Lample et al., NeurIPS 2019, arXiv 1907.05242, and **Memory Layers at Scale**, Berges et al., ICML 2025, arXiv 2412.09764 (up to 128B memory params). **Hash Layers**, Roller et al., NeurIPS 2021, arXiv 2106.04426 (routing by token hash). These are static learned memories. Extension: a product-key read over the in-context successor embeddings as a learned "which of the k candidates" selector.

## E. Why a recurrent state needs this (motivation)

- **Zoology**, Arora et al., ICLR 2024, arXiv 2312.04927: 82% of the quality gap to attention comes from in-context recall.
- **Repeat After Me**, Jelassi et al., ICML 2024, arXiv 2402.01032: fixed-state models cannot copy.
- **Hybrid Linear Attention analysis**, 2025, arXiv 2507.06457: recall improves with more full-attention layers, especially below 3:1 (snippet only).
- **Retrievit**, 2026, arXiv 2603.02874: n-gram retrieval tests for hybrids (snippet only).

## Most promising directions (ranked)

1. **Multi-candidate successor set with counts (SuffixDecoding, Token Recycling, SAM).** Replace s* by the top-k successors with counts and the fraction of mass on the top one. Pass the distribution in, not a single token. This attacks over-reliance directly (a "disagree" case becomes a spread-out distribution). It is cheap, CPU-only, and a clean ablation (C vs C_topk). Trust signals barely helped because they are a scalar summary of the same single token.
2. **Output as a mixture, not a bonus (pointer-sentinel, neural cache, Drozdov).** Use a gated mixture p = g*p_copy + (1-g)*p_LM, with g from the hidden state and the match features. Calibrate by bucket. A mixture can abstain, and the model's wrong-lookup loss should fall. It also explains why C is worse than B where the lookup is wrong.
3. **Quantized-hidden-state n-grams (N-Grammer, SimHash/Reformer, kNN-LM keys).** Match on short codes of a frozen layer-2 state. This gives paraphrase and "same entity, different wording" matching at 2-4 B/token extra, still about 50x below KV. It addresses the reviewers' complaint that ICE cannot do paraphrase. Risk: moderate engineering, and collisions need careful measurement.
4. **Span extension (NEST, COG).** Confident long match leads to feeding the next k successor tokens. Helps long copy and identifier cases (config values), and reduces per-token overhead.
5. **ICE + Engram 2x2 (static x in-context), with FactorEngram-style basis gating.** A clean "story" for faculty: static n-gram memory for knowledge, in-context n-gram memory for recall. Engram precedent makes the framing credible.

## Novelty risk summary

- No paper found that does exactly "exact in-context n-gram successor lookup (CPU hash table, multi-order, match-length and distance buckets, plus output logit bonus) injected into a GDN/attention hybrid". Search for this specific combination returned nothing.
- Near misses: HOLA 2607.02303 (exact KV cache for a linear model, same motivation, much higher memory); Akyurek n-gram heads (attention based); the neural cache and pointer-sentinel (hidden-state, old, RNN era); infini-gram (offline corpus); Engram (static). The claim should be stated as "bytes per token, causal, CPU, in-context recall for hybrids" and be compared against HOLA on the Pareto.
- The over-reliance finding is well precedented (kNN-LM misleading neighbors, 2305.14625), so frame it as a known failure that ICE-with-candidates mitigates, not as a new discovery.
- Searches were broad but not exhaustive. Prompt Lookup Decoding has no paper, and I did not check LLM-code-specific copy work.
